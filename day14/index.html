#2

Model view: the relationship on TerritoryID

-- Model view: Territory (1) to reporting SalesSummary (*) on TerritoryID
-- Cardinality: Many to one (*:1)    Cross-filter direction: Single

What this step does

Power BI created the relationship by itself on Load, because both tables have a TerritoryID column. Many to one: many SalesSummary rows (one per territory per month) point to one Territory row. Single cross-filter means filters flow from Territory to SalesSummary, which is what lets a Territory Name slicer filter revenue.

#3

A Date column from YearMonth

Date = DATE(VALUE(LEFT('reporting SalesSummary'[YearMonth], 4)), VALUE(MID('reporting SalesSummary'[YearMonth], 6, 2)), 1)
-- Data type: Date    Format: Mmm yyyy

What this step does

YearMonth is text such as 2012-05, and a line chart needs a real date to space the months correctly. The formula takes the year and month out of the text and builds the first day of that month. Power Query is usually the better place for this kind of shaping, because then the model only holds finished columns; for one column on a small table both work.

📍 The plan builds this column in Power Query: Date.FromText([YearMonth] & "-01"). I wrote it as a DAX calculated column instead. The result is the same column.

#4

The DAX measure: Avg Order Value

Avg Order Value = DIVIDE(SUM('reporting SalesSummary'[Revenue]), SUM('reporting SalesSummary'[OrderCount]))
Total Revenue = SUM('reporting SalesSummary'[Revenue])

What this step does

A measure is worked out when a visual asks for it, for whatever that visual is filtered to: 3,916 for all territories, a different number for Canada alone. DIVIDE returns blank instead of an error if the order count is 0. It divides the sums, rather than averaging the stored AvgOrderValue column, because an average of monthly averages gives a small month the same weight as a big one. Total Revenue is a second measure so the card has a clear name.

Part 3: week 2 assessment, SQL

#11

Q1. Rank territories by 2013 revenue with DENSE_RANK

USE AWPractice;
SELECT t.Name AS Territory, SUM(h.TotalDue) AS Revenue2013,
       DENSE_RANK() OVER (ORDER BY SUM(h.TotalDue) DESC) AS RevenueRank
FROM SalesOrderHeader h
JOIN Territory t ON h.TerritoryID = t.TerritoryID
WHERE h.OrderDate >= '2013-01-01' AND h.OrderDate < '2014-01-01'
GROUP BY t.Name;

What this query does

Group 2013 orders by territory, then DENSE_RANK over the grouped totals (Day 8, drill 8 shape: a window function can use an aggregate because it runs after GROUP BY). The date filter is a range, not YEAR(), so it could use an index on OrderDate (Day 12). Southwest ranks 1.

#12

Q2. Each customer's order count and days between first and last order, window functions, no self-join

SELECT DISTINCT CustomerID,
       COUNT(*) OVER (PARTITION BY CustomerID) AS Orders,
       DATEDIFF(day, MIN(OrderDate) OVER (PARTITION BY CustomerID),
                     MAX(OrderDate) OVER (PARTITION BY CustomerID)) AS DaysFirstToLast
FROM SalesOrderHeader
ORDER BY Orders DESC, CustomerID;

What this query does

COUNT, MIN and MAX with OVER (PARTITION BY CustomerID) put each customer's totals on every one of their orders without collapsing the rows; DISTINCT then keeps one row per customer. A plain GROUP BY would give the same answer more cheaply, but the question asks for window functions. 19,119 customers.

#13

Q3. Three-month moving average of monthly revenue

WITH Monthly AS (
    SELECT CONVERT(char(7), OrderDate, 120) AS YearMonth, SUM(TotalDue) AS Revenue
    FROM SalesOrderHeader GROUP BY CONVERT(char(7), OrderDate, 120)
)
SELECT YearMonth, Revenue,
       AVG(Revenue) OVER (ORDER BY YearMonth ROWS BETWEEN 2 PRECEDING AND CURRENT ROW) AS MovingAvg3
FROM Monthly ORDER BY YearMonth;

What this query does

Monthly totals in a CTE, then AVG over a sliding frame of this row and the two before it (Day 8 stretch). CONVERT(char(7), ..., 120) gives a short 'yyyy-mm' label, which avoids the FORMAT/RANGE error from Day 8 drill 5 and is faster. 38 months.

#14

Q4. Inside a transaction, raise all Bike prices 5 percent, show the OUTPUT, roll back

BEGIN TRANSACTION;
UPDATE p SET p.ListPrice = p.ListPrice * 1.05
OUTPUT inserted.ProductID, inserted.Name, deleted.ListPrice AS OldPrice, inserted.ListPrice AS NewPrice
FROM Product p
JOIN AdventureWorks2022.Production.ProductSubcategory s ON p.ProductSubcategoryID = s.ProductSubcategoryID
WHERE s.ProductCategoryID = 1;   -- 1 = Bikes
ROLLBACK TRANSACTION;
SELECT COUNT(*) AS BikesStillAtOldPrice FROM Product p
JOIN AdventureWorks2022.Production.ProductSubcategory s ON p.ProductSubcategoryID = s.ProductSubcategoryID
WHERE s.ProductCategoryID = 1;

What this query does

UPDATE with a JOIN (Day 9 drill 6) limited to category 1, Bikes. OUTPUT returns each changed row with deleted (before) and inserted (after) prices side by side: 97 bikes. ROLLBACK undoes all of it, so nothing is changed permanently.

#15

Q5. MERGE a two-row staging table into Territory: one update, one insert

TRUNCATE TABLE TerritoryStaging;
INSERT INTO TerritoryStaging (TerritoryID, Name, CountryRegionCode, [Group])
VALUES (11, 'Pakistan (South Asia)', 'PK', 'Asia'), (15, 'Sri Lanka', 'LK', 'Asia');
SET IDENTITY_INSERT Territory ON;
MERGE Territory AS target
USING TerritoryStaging AS source ON target.TerritoryID = source.TerritoryID
WHEN MATCHED THEN UPDATE SET target.Name = source.Name
WHEN NOT MATCHED THEN INSERT (TerritoryID, Name, CountryRegionCode, [Group], SalesYTD, SalesLastYear,
                              CostYTD, CostLastYear, rowguid, ModifiedDate)
     VALUES (source.TerritoryID, source.Name, source.CountryRegionCode, source.[Group], 0, 0, 0, 0, NEWID(), GETDATE())
OUTPUT $action, inserted.TerritoryID, inserted.Name;
SET IDENTITY_INSERT Territory OFF;

What this query does

Two staging rows: 11 already exists, so MERGE updates its name; 15 is new, so it is inserted. OUTPUT $action shows UPDATE and INSERT. IDENTITY_INSERT is needed because Territory kept its identity column (Day 9).

#16

Q6. reporting.TerritoryMonthly with a composite key, CHECK on Revenue, and a foreign key to Territory

DROP TABLE IF EXISTS reporting.TerritoryMonthly;
CREATE TABLE reporting.TerritoryMonthly (
    TerritoryID INT NOT NULL,
    YearMonth CHAR(7) NOT NULL,
    OrderCount INT NOT NULL,
    Revenue DECIMAL(18,2) NOT NULL CONSTRAINT CK_TerritoryMonthly_Revenue CHECK (Revenue >= 0),
    CONSTRAINT PK_TerritoryMonthly PRIMARY KEY (TerritoryID, YearMonth),
    CONSTRAINT FK_TerritoryMonthly_Territory FOREIGN KEY (TerritoryID) REFERENCES Territory(TerritoryID)
);
SELECT name, type_desc FROM sys.objects WHERE parent_object_id = OBJECT_ID('reporting.TerritoryMonthly');

What this query does

Composite primary key: one row per territory per month. Named CHECK and FOREIGN KEY constraints (Day 10). The last SELECT lists the three constraints, proving they exist.

Q7. A view that adds the territory name and country

CREATE OR ALTER VIEW reporting.vw_TerritoryMonthly AS
SELECT tm.TerritoryID, t.Name AS Territory, t.CountryRegionCode AS Country,
       tm.YearMonth, tm.OrderCount, tm.Revenue
FROM reporting.TerritoryMonthly tm
JOIN Territory t ON tm.TerritoryID = t.TerritoryID;

What this query does

CREATE OR ALTER makes the view re-runnable. The join to Territory supplies name and country code; the foreign key guarantees every TerritoryID has a match, so the INNER JOIN never drops rows.

#18

Q8. A procedure that loads it with TRY/CATCH and returns the row count

CREATE OR ALTER PROCEDURE reporting.usp_LoadTerritoryMonthly
AS
BEGIN
    SET NOCOUNT ON;
    BEGIN TRY
        BEGIN TRANSACTION;
        DELETE FROM reporting.TerritoryMonthly;
        INSERT INTO reporting.TerritoryMonthly (TerritoryID, YearMonth, OrderCount, Revenue)
        SELECT TerritoryID, CONVERT(char(7), OrderDate, 120), COUNT(*), SUM(TotalDue)
        FROM SalesOrderHeader GROUP BY TerritoryID, CONVERT(char(7), OrderDate, 120);
        DECLARE @Rows INT = @@ROWCOUNT;
        COMMIT TRANSACTION;
        SELECT @Rows AS RowsLoaded;
    END TRY
    BEGIN CATCH
        IF @@TRANCOUNT > 0 ROLLBACK TRANSACTION;
        THROW;
    END CATCH
END;
GO
EXEC reporting.usp_LoadTerritoryMonthly;
SELECT TOP 5 * FROM reporting.vw_TerritoryMonthly ORDER BY Revenue DESC;

What this query does

The Day 11 load shape: transaction, delete, insert, save @@ROWCOUNT, commit; on any error roll back and re-THROW so the caller sees the failure. 364 rows loaded. The SELECT from the Q7 view proves the view works on the loaded data.

Q9. A function returning price band, used in a SELECT

CREATE OR ALTER FUNCTION dbo.fn_PriceBand (@Price MONEY)
RETURNS VARCHAR(10)
AS
BEGIN
    RETURN CASE WHEN @Price < 100 THEN 'Budget' WHEN @Price < 1000 THEN 'Mid' ELSE 'Premium' END;
END;
GO
SELECT dbo.fn_PriceBand(ListPrice) AS Band, COUNT(*) AS Products
FROM Product WHERE ListPrice > 0
GROUP BY dbo.fn_PriceBand(ListPrice);

What this query does

The Day 11 scalar function, used in both SELECT and GROUP BY to count products per band.

Part 3: short answers (SSIS and Power BI)

1. What are the two canvases in an SSIS package and what goes on each?
Control Flow holds the tasks and the order they run in: Execute SQL Tasks, Data Flow Tasks, containers, joined by precedence constraints (the green arrows). Data Flow is the inside of one Data Flow Task: the rows moving from sources through transformations to destinations.

2. Why did the first rerun of LoadSalesSummary fail and what are two ways to fix it?
The table has a UNIQUE key on (TerritoryID, YearMonth), and the rerun tried to insert the same rows a second time. Fix 1: an Execute SQL Task that truncates (or deletes from) the target before the data flow, which is what the package does now. Fix 2: load into a staging table and MERGE into the target, or use a Lookup so only new rows are inserted.

3. What does a Data Conversion transform do and when do you need one?
It copies a column into a new column with a different SSIS data type. You need one when the source and destination types do not match and SSIS will not convert them by itself, most often Unicode text (DT_WSTR, nvarchar) going into a non-Unicode column (DT_STR, varchar), as with YearMonth from FORMAT().

4. What is the difference between Import and DirectQuery in Power BI?
Import copies the data into the Power BI model: fast visuals, but only as fresh as the last refresh, and the data has to fit in the model. DirectQuery stores no data and sends a query to the database every time a visual draws: always current, but slower, it puts load on the source, and some DAX features are limited.

5. What does a relationship in the Model view do that a JOIN does in SQL?
It tells the model how two tables match: the key column, the cardinality (many to one) and which way filters flow. You define it once, and every visual then combines the tables through it automatically, the way a JOIN combines them in a single query. Filters also travel along it, which is how the Territory slicer filters SalesSummary.
